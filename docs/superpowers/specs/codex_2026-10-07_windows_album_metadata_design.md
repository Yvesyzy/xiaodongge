# Windows 当前播放专辑和歌手补全

Yves 于 2026-10-07 要求比较解决办法后直接实施。本次目标是让 Windows 读取当前网易云歌曲时获取可确认的专辑和完整歌手，并交付实际可运行程序。

## 已确认的问题

网易云音乐 3.1.41.205529 已开启 SMTC，Windows 系统会话对《当你环绕我》只返回 `Title = 当你环绕我`、`Artist = 周乘羽`、`AlbumTitle = 空`。窗口显示歌手为周乘羽/卡力老虎/Matt吕彦良。原 Windows 程序及表单已复现目录补全没有匹配；这使默认专辑记录退回歌曲记录。

## 路径比较

1. 系统媒体会话继续负责确认正在播放的来源和歌曲；它已经报告的空专辑无法由重新读同一接口补出。
2. 使用已核实的 `%LOCALAPPDATA%\NetEase\CloudMusic\webdata\file\playingList`。UTF-8 JSON 顶层只有 `list` 数组；有效记录的 `resourceType` 是 `track`，曲目位于 `item.track`。`track.id` 为数字字符串，`track.name` 为歌名，`track.artists[].name` 为完整歌手，`track.album.name` 为专辑。两首歌各唯一出现一次，专辑均为《商业与玩法》。只读此队列，不使用缺少目标的 `lastTimePlayingList` 或独立 FM 队列。`fromInfo.sourceData` 和外层 `text` 属于来源页面，已证实不能识别当前歌曲。
3. Apple iTunes 目录保留为现有联网补全路径。只读调查已比较 CN/US 的完整查询、只搜歌名及最高 200 条结果，没有两首目标歌曲的精确记录；本次不改共享匹配规则或查询上限。[Apple 官方 Search API 文档](https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/iTuneSearchAPI/Searching.html)。
4. 截图 OCR 保留现有人工入口。新增自动截图识别和未核实的第三方接口会增加不必要的不确定性；本次优先现成结构化数据。

## 实现边界

- Windows 主进程在 `getCurrentTrack` 内对已确认正在播放的网易云曲目补全；所有调用方继续使用现有返回结构。
- 只有 `musicMetadata.sourcePackage === cloudmusic.exe`、歌曲名和艺术家可确认、来源记录唯一且没有专辑冲突时补全。暂停、空会话及其他播放器保持已有处理规则。
- 外部本机文件损坏、缺失、超过读取限制、数据不完整或存在不同版本时保留原系统返回；不从历史记录推断当前歌曲。
- 只填充现有公开字段；保留来源、已有身份信息、表单修订守卫和草稿/正式保存规则。不得把网易云 ID 写到 Apple 目录 ID 字段。
- 不改存储结构，不写网易云配置或数据库，不添加依赖，不把本机队列或个人档案放入运行包。
- 本机 JSON 最多读取 8 MiB；用带终止位置的标准库流限制读取量，超限或读取失败直接返回系统结果。名字沿用现有 NFKC、去空白和大小写规范化，仅精确匹配歌曲及歌手；多个版本即使其中一个有专辑也不取第一项。
- 队列没有当前歌曲 ID 或索引。系统会话是当前播放的唯一依据，本机队列只提供已匹配曲目的专辑和完整歌手；不改变播放会话选择。

## 验收与交付

最小检查覆盖完整歌手/专辑、其他播放器、暂停返回、同名不同歌手、同曲不同版本、已有专辑冲突、损坏及超限文件。真实网易云播放在独立 Windows profile 内确认默认专辑记录、来源歌曲、歌手字段和无正式自动保存，另核对原有 Windows 检查。最终交付新的完整便携程序和 ZIP，核对包内源码、文件清单和 SHA-256；按持续规则清理本聊天已完成任务的临时输出。

自审结论：当前播放可信边界、实际字段、所有表单调用方和包内依赖已核对。Yves 已要求直接实施；无需再次确认设计。
