# Android 原生导出、分享与复制修复设计

## 1. 背景

v2.1.9 的备份页可以正常生成 JSON、TXT、CSV 内容，但 Android App 中“保存/分享文件”和“复制内容”没有可见结果。当前实现直接从 WebView 调用 Capacitor Filesystem 和浏览器剪贴板接口；保存按钮也没有真正进入 Android 系统分享流程。页面反馈位于导入表单下方，用户在导出区域看不到执行结果。

## 2. 目标

1. 将原来含义混合的“保存/分享文件”拆为“保存到文件夹”和“系统分享”。
2. 保存时打开 Android 系统文件创建器，由用户选择系统文件夹和文件名。
3. 分享时向 Android 系统分享面板传递真实文件附件。
4. 复制时使用 Android 原生剪贴板，并保留浏览器兼容路径。
5. 在三个操作按钮旁立即显示处理中、成功、取消或失败状态。
6. JSON 备份健康状态只在文件确认写入成功后更新。

## 3. 方案

新增本地 Capacitor 插件 `NativeExportPlugin`，不引入第三方依赖：

- `saveFile` 使用 `Intent.ACTION_CREATE_DOCUMENT`，把 UTF-8 内容写入系统返回的 `content://` URI。
- `shareFile` 把 UTF-8 内容写入 App 缓存目录，通过现有 `FileProvider` 生成只读 URI，再使用 `Intent.ACTION_SEND` 打开系统分享面板。
- `copyText` 使用 Android `ClipboardManager` 写入系统剪贴板。

前端新增类型化桥接 `nativeExport.ts`。Android 环境调用原生插件；浏览器环境继续使用下载、Web Share API 和浏览器剪贴板回退逻辑。

## 4. 交互与状态

导出内容下方固定提供三个按钮：

1. 保存到文件夹
2. 系统分享
3. 复制内容

执行期间只禁用这三个按钮，避免重复打开系统窗口。按钮下方使用可访问的实时状态区域反馈：

- 正在打开系统文件选择器……
- 文件已保存
- 已取消保存
- 已打开系统分享
- 内容已复制
- 具体失败原因

## 5. 错误处理与数据边界

- 原生层校验文件名、MIME 类型和内容参数，不补造缺失字段。
- 系统取消保存视为正常结果，不显示为错误。
- 文件输出流必须通过自动关闭机制关闭，写入失败返回明确错误。
- 分享 URI 只授予接收应用临时只读权限。
- 分享缓存文件存放在专用 `exports/` 目录。
- 不申请 Android 广泛存储权限，也不直接写入猜测的公共目录路径。

## 6. 验证范围

1. 自动检查原生插件注册、系统 Intent、TypeScript 桥接和三个按钮接线。
2. 运行现有 JSON、TXT、CSV 导出格式检查。
3. 运行 TypeScript 类型检查和移动端生产构建。
4. 执行 Capacitor 同步并编译 Android debug APK。
5. 真机确认三种格式均可保存到用户选择的文件夹、分享为附件，并能粘贴复制内容。

## 7. 非目标

- 不修改导出数据格式或 SQLite 备份版本。
- 不增加云同步或后台自动备份。
- 不申请外部存储管理权限。
- 不重构备份页之外的模块。
