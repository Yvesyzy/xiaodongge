# 本地语义音乐年鉴设计

## 背景

当前 Android 移动端的年度总结由 `mobile/src/summary.ts` 生成 Markdown 长文，主要包含记录数量、高频标签、高频情绪、月份归纳和原文片段。它能够整理已有记录，但没有系统分析评价正文，也缺少适合年度回顾的叙事与视觉层次。

本次改造将年度总结升级为“私人听感标本册”：完全基于手机本地数据，通过可解释的词典和语义规则分析用户如何描述音乐，再用唱片册与音乐标本馆结合的视觉语言呈现。功能不统计收听时长，不调用在线 AI，不上传评价正文。

## 目标

- 从评价正文中识别情绪、风格、旋律、节奏和表达方式词语。
- 生成有明确证据、能够回看原文的年度听感总结。
- 根据数据量自动生成记忆卡、精简年鉴或完整年鉴。
- 将结果呈现为有收藏感的移动端年度作品，而不是普通统计面板。
- 保持分析确定、可解释、离线可用，并兼容旧总结与旧备份。

## 范围

### 包含

- Android 移动端及其浏览器预览模式中的本地年度分析。
- 情绪、风格、旋律、节奏四类听感词典。
- 空间、画面、身体感受、音乐结构和个人联想五类表达方式词典。
- 同义词归并、最长词优先、否定识别、程度词记录和转折分句。
- 结构化年度分析快照、确定性文字模板和原文证据引用。
- 三种数据充分度对应的年度展示模式。
- “私人听感标本册”全屏阅读界面、原文证据面板及统计说明。
- SQLite、localStorage 和 JSON 备份中的新旧数据兼容。

### 不包含

- 在线 AI、云端同步或服务端分析。
- 收听时长、播放次数、年度播放排行或外部音乐平台数据。
- 根据歌曲名、艺术家或外部资料自动推断曲风。
- 心理诊断、性格判断或没有原文证据的审美结论。
- 长图导出、社交分享、3D 年鉴或新的封面生成能力。
- 电脑端 Next.js 年度总结页面的同步改造。

## 核心产品原则

1. 先说明页面回答的问题，再展示图形。
2. 所有统计图都标明数值、单位和统计口径。
3. 抽象形态只作为“年度听感印章”，不承担未解释的数据编码。
4. 重要结论必须关联原文证据，最多两步可以回到原记录。
5. 证据不足时隐藏章节或明确显示“今年较少描述这一方面”。
6. 不把词频直接解释为用户人格或心理状态。
7. 同一数据和同一分析版本必须生成完全相同的结果。

## 年鉴模式

数据充分度按所选年份内正文去除首尾空白后非空的记录数计算：

- `1–2` 篇：生成“年度记忆卡”，包含基础概览、已识别词语和原文片段。
- `3–7` 篇：生成四屏精简版，包含卷首、四维听感、语言标本和留声。
- `8` 篇及以上：生成完整八屏版；单个证据不足的章节仍可隐藏。
- `0` 篇：不生成，提示先添加该年份的音乐评价。

模式只决定可用章节，不降低单条结论的证据门槛。

## 年鉴章节

### 1. 卷首：年度听感题名

用两个证据最充分的维度生成一句诗性题名，例如“在声音里寻找空间的人”。页面同时列出题名使用的主词和数据依据。该题名是年度作品标题，不标记为人格或心理结论。

只有完整模式中至少两个维度分别满足“稳定主词”规则时才生成题名；否则使用中性标题“我的 2026 音乐感受年鉴”。

### 2. 这一年留下了什么

简洁展示评价篇数、涉及歌曲数、涉及专辑数和正文总字符数。基础数字只提供上下文，不作为叙事主角，不展示收听时长。

### 3. 年度语言标本

展示经过词典识别和同义归并后的年度主词、高频原始表达及对应句子。排除“音乐、歌曲、感觉、好听”等不提供听感信息的通用词。第一版不做自由分词词云，避免把无意义的高频词包装成结论。

### 4. 四维听感解剖

分别展示情绪、风格、旋律和节奏：

- 主词及其出现次数。
- 涉及评价数。
- 次高词及精确次数。
- 可打开的原文证据。

同页横条全部使用出现次数作为长度，并共享同一最大值。年度听感印章明确标记为装饰元素。

### 5. 情绪轨迹

按月份展示有足够记录的情绪变化。一个月份至少有 `2` 篇包含已识别情绪词的评价才进入轨迹；至少有 `3` 个满足条件的月份才显示整个章节。没有月份或数据不足时隐藏，不用创建时间或生成时间补齐。

### 6. 你的评价方式

使用表达方式词典统计用户更常描述空间、画面、身体感受、音乐结构还是个人联想。每类展示主词、覆盖评价数和原句，不使用“专业”“感性”等价值判断。

### 7. 年度发现

最多展示两条满足固定规则的关系或变化：

- 前后半年变化：两个半年分别至少有 `4` 篇带月份且含有效命中的评价；同一归一化词的评价覆盖率相差至少 `30` 个百分点，评价覆盖数相差至少 `2` 篇。
- 评分关联：至少有 `8` 篇已评分且含有效命中的评价；`8–10` 分组和 `1–7` 分组分别至少有 `3` 篇；同一归一化词的评价覆盖率相差至少 `30` 个百分点，并在覆盖率更高的分组中涉及至少 `3` 篇评价。

满足规则时只描述数据关系，例如“8–10 分评价中更常出现‘层次’”，不写成因果关系。没有满足条件的发现时隐藏整章。

### 8. 留声：原文与结语

展示 `3–5` 条来自不同记录的代表原句。符合条件的句子长度为 `12–120` 个 Unicode 字符，按命中的不同归一化词数量排序，优先覆盖不同月份和不同记录；最终并列时按记录时间和句子在正文中的顺序确定。点击句子返回原记录。

结语使用固定模板概括有证据的主词和表达方式，不补写用户没有表达过的感受。

## 本地分析规则

### 文本预处理

1. 对分析副本执行 Unicode NFKC 规范化。
2. 合并连续空白并统一换行；原始正文不修改。
3. 使用 `。！？!?；;` 和换行切分句子。
4. 使用“但、但是、不过、却、反而、后来、随后”继续切分转折分句并保留原顺序。
5. 拉丁字符匹配时不区分大小写；中文保持原字符。

### 词典结构

每个词典条目具有稳定顺序，并包含：

- 所属类别。
- 归一化词。
- 一个或多个原始变体。
- 可空的上下文限定词。

第一版不把“轻、慢、重”等单个歧义字作为独立变体；使用“轻盈、轻快、缓慢、厚重”等能够明确分类的词组。词典作为本地版本化数据随 APK 发布，不从网络更新。

### 匹配与归并

1. 在每个分句中按变体长度从长到短匹配。
2. 较长变体已经覆盖的字符区间不再被较短变体重复命中。
3. 命中保存归一化词、原始表达、类别、句子、记录 ID、月份和字符位置。
4. 同一句出现多次相同表达时记录真实出现次数；评价覆盖数按记录 ID 去重。
5. 排名依次使用评价覆盖数、出现次数和词典声明顺序，保证稳定结果。

### 否定、程度和转折

- 命中前同一分句内 `4` 个 Unicode 字符范围出现“不、不太、并不、没有、没、未、谈不上、算不上”时，该命中标记为否定，不进入正向次数。
- “不只、不只是、不仅”不作为否定前缀。
- “稍微、略微、有点、很、非常、格外、极其”等程度词随命中保存，仅用于原文说明；第一版不改变出现次数或横条长度。
- 转折前后分句分别分析，不用后一句覆盖前一句。

### 稳定主词与缺失状态

完整模式中，一个归一化词同时满足以下条件才是“稳定主词”：

- 涉及至少 `3` 篇评价。
- 覆盖所选年份至少 `25%` 的可分析评价。

四维页面仍可展示出现至少 `2` 次或涉及至少 `2` 篇评价的词，但不得称为稳定倾向。某个维度没有达到展示门槛时显示“今年较少描述这一方面”。

## 结构化分析快照

新结果先生成结构化快照，再由界面和文本模板分别消费。快照固定包含：

- `version`：分析结构版本。
- `year`、生成时间、来源记录数和正文总字符数。
- `mode`：记忆卡、精简版或完整版。
- 基础概览。
- 四维听感统计。
- 表达方式统计。
- 月份轨迹。
- 年度发现。
- 代表原句。
- 每个结论的记录 ID 和原句证据。
- 被隐藏章节及其原因。

快照不复制完整评价正文，只保存实际展示或用于核查的证据句。所有快照字段在 SQLite、localStorage 和备份导入边界进行类型验证。

## 数据模型与兼容

现有 `YearlySummary` 保留 `content` 字段作为旧版展示和 TXT 导出的可读文本，新增：

- 可空的结构化分析 JSON 文本列。
- 可空的分析版本整数列。

旧行读取为“无结构化快照”，继续使用当前 Markdown 展示。用户重新生成后写入结构化快照，同时从同一快照生成确定性 `content` 文本，避免两份结论漂移。

SQLite 初始化检查新列是否存在，缺少时各执行一次加列迁移，不重写旧总结。迁移失败时停止数据库打开，避免部分迁移后的写入。

当前工作树的 JSON 备份格式为版本 2；实现本功能时升级为版本 3，并继续接受版本 1 和版本 2。版本 3 导出结构化快照和分析版本；旧备份缺少这些字段时按空值处理。导入前快照、导入撤销和浏览器 localStorage 路径必须保留相同行为。

新增、编辑或删除评价后，继续使用当前按年份删除已保存总结的失效机制。分析规则版本升级不自动删除旧结果；打开旧结果时提示“分析方法已更新”，由用户主动重新生成。

## 组件与数据流

功能分为五个边界清晰的单元：

1. 本地词典：只声明类别、归一化词、变体和上下文限制。
2. 文本分析器：接收评价数组，输出命中与证据，不生成界面文案。
3. 年度聚合器：计算覆盖数、轨迹、发现、充分度和隐藏原因。
4. 年度文案生成器：只根据结构化快照套用确定性模板。
5. 年鉴阅读器：渲染章节、动画和证据面板，不重新计算统计。

生成流程：

1. 用户选择年份，页面读取本地评价并显示数据充分度。
2. 用户点击“生成本地音乐年鉴”。
3. 文本分析器生成逐句命中和证据。
4. 年度聚合器生成结构化快照。
5. 文案生成器生成可读 `content`。
6. 所有步骤成功后一次性保存新总结。
7. 界面进入全屏年鉴阅读器；失败时保留上一次成功结果。

## 交互与视觉

- 入口沿用现有年度总结页，生成前展示年份、可分析评价数、正文字符数和将使用的年鉴模式。
- 生成按钮命名为“生成本地音乐年鉴”。
- 年鉴采用纵向滑动，顶部固定显示章节序号，例如 `02 / 08`。
- 点击高频词打开证据面板；点击证据返回对应评价详情。
- 点击月份查看该月主词和相关记录。
- 点击“统计说明”查看归并、否定和计数规则。
- 记录变化后显示重新生成入口；生成过程不展示虚假百分比。

视觉采用已确认的“情绪唱片册 + 音乐标本馆”方向：

- 暖纸张、深酒红、松石绿和旧金色为主色。
- 唱片、档案编号、标本注释线和听感印章构成视觉语言。
- 情绪、风格、旋律、节奏分别使用固定颜色，并在首次出现时显示图例。
- 所有横条和时间图显示数值、单位及统计口径。
- 不使用含义不明确的词云或无图例抽象统计图。
- 动效限于翻页、纸张位移、印章显影和线条绘制；系统开启减少动态效果时关闭大幅动画。
- 章节按需渲染，避免进入页面时同时播放全部动画。

## 错误处理

- 没有记录：不生成并提示先写评价。
- 正文记录少于 `3` 篇：生成记忆卡，不生成趋势和年度发现。
- 单条记录无法分析：跳过该条的语义统计，但保留其基础概览；不让整本年鉴失败。
- 某个维度无有效词：显示明确缺失状态，不使用其他字段猜测。
- 保存失败：保留旧总结并显示错误，不写入半成品。
- 结构化快照校验失败：不渲染年鉴，回退旧 `content` 或提示重新生成。
- 证据指向的记录已不存在：证据面板标记“原记录已删除”，其余年鉴内容仍可阅读。

## 隐私与性能

- 分析在 JavaScript 和本地 SQLite 数据上完成，不发起网络请求。
- 不新增 Android 网络权限；已有其他功能的网络能力不参与年度分析。
- 不加载模型文件，不新增大型 NLP 依赖。
- 词典与规则执行以年度记录总字符数线性扫描为目标。
- 只保存展示所需证据句，不重复保存完整正文。

## 验证

### 分析规则

- 同义词正确归并并保留原始表达。
- 否定表达不进入正向计数，“不只、不只是、不仅”不被误判。
- 转折分句分别保留命中。
- 最长词优先且重叠区间不重复累计。
- 出现次数、评价覆盖数和月份覆盖数分别计算。
- 相同输入和分析版本生成完全一致的快照和文本。
- 每条题名、趋势和年度发现均有关联证据。
- 所有门槛边界分别覆盖低于、等于和高于阈值的情况。

### 数据与兼容

- SQLite 旧库加列迁移后可读写新旧总结。
- 版本 1、版本 2 备份可导入；版本 3 可完整导出和恢复。
- 浏览器 localStorage 与 Android SQLite 生成相同分析结果。
- 新增、编辑和删除评价后，对应年份总结正确失效。
- 重新生成失败不会覆盖旧总结。
- 缺少月份、评分、歌曲、专辑或艺术家时仍可完成正文分析。
- 年度分析执行期间不产生网络请求。

### 界面

- 每张数据图能直接判断展示内容、数值和单位。
- 抽象听感印章不会被误解为统计图。
- 重要结论最多两步打开原文证据。
- 三种数据量模式均有完整空状态和降级展示。
- 超长正文、歌曲名、专辑名和系统大字体不破坏布局。
- 减少动态效果模式关闭非必要动画。
- 小屏 Android 设备可完成生成、翻阅、查看证据和返回记录的完整流程。

最小检查包括 TypeScript 检查、本地分析脚本、现有移动端检查、移动端生产构建和 Android debug APK 构建。

## 成功标准

- 用户无需联网即可生成并保存年度音乐年鉴。
- 用户能看懂每个结论表达什么、使用什么单位、为什么得出。
- 重要结论可以回到真实原文，不出现数据库外的感受或曲风。
- 数据不足时功能主动降级，不制造趋势或人格判断。
- 旧总结、旧数据库和旧备份继续可用。
- 年鉴保持明确的私人唱片册与音乐标本馆审美，并在小屏 Android 上流畅阅读。
