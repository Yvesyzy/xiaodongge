# v2.1.0 私人听感标本册改进总方案

## 背景与版本目标

v2.0.1 已具备音乐评价、歌曲与专辑聚合、标签与情绪、年度 Markdown 总结、本地备份和 Android 本地存储等能力。v2.1.0 在不改变现有乐评录入、查询、编辑、删除、封面、可视化、备份和当前播放识别行为的前提下，把总结升级为“私人听感标本册”。

产品不统计收听时长，不使用在线 AI，不上传乐评正文。它通过手机本地的词典与语义规则，分析用户如何感受、评价和描述音乐，再把结果组织为乐评内的当日注记、十二套月度作品和年度标本册。

## 总体数据流

```text
乐评原文
  -> 本地分句与语义命中
  -> 对象、描述词、表达方式与证据
  -> 乐评内当日听感注记
  -> 月度结构化快照与月度作品
  -> 年度聚合、审美迁徙与年度标本册
```

系统生成的文案永不作为下一层分析输入。年度只合并月度结构化快照与无月份记录的独立分析，避免分析系统自己的文字或重复计算同一篇乐评。

## 1. 产品结构

功能分为三个层级：

1. 单篇乐评内嵌“当日听感注记”，不新增每日总结入口。
2. 月份生成独立的月度听感作品，使用十二套月度美术主题。
3. 年度生成“私人听感标本册”，汇总全年感受、关注对象、表达习惯和审美迁徙。

现有人工 `month` 类型记录作为“本月自述”单独呈现，不进入自动词频。现有人工 `year` 类型记录保持普通乐评身份，不被系统生成的年度总结覆盖。

## 2. 本地语义分析

### 三层语义模型

- 感受到什么：情绪、审美感受、曲风和氛围描述。
- 评价什么：人声、旋律、节奏、歌词、编曲、音色、制作、空间与层次。
- 如何表达：画面感、空间感、身体感受、回忆联想、技术描述和场景描写。

分析以分句为单位保存“评价对象 × 描述词”，例如“人声 × 温柔”“节奏 × 强烈”。每次命中保留归一化词、原始表达、类别、分句、记录 ID 和原文位置。

### 规则

1. 分析副本执行 Unicode NFKC 规范化，原文保持不变。
2. 以中文标点、换行及转折词分句。
3. 同义词归并为统一词，最长匹配优先，重叠区间不重复计数。
4. 识别“不、没有、谈不上”等否定前缀；“不只、不仅”等不作为否定。
5. 保存“稍微、很、非常、格外”等程度词，但第一版不人为放大计数。
6. 转折前后分别分析，不使用后一分句覆盖前一分句。
7. 曲风只来自正文、已选曲风标签或可信音乐元数据，不根据歌曲名、歌手名猜测。

### 统计单位

同时保留：

- 出现次数：词语实际命中次数。
- 乐评覆盖数：至少命中一次的不同乐评数量。
- 乐评日覆盖数：至少命中一次的不同精确日期数量。
- 月份覆盖数：至少命中一次的不同月份数量。

排名依次按乐评覆盖数、出现次数和词典声明顺序确定，保证相同输入和分析版本生成相同结果。

## 3. 乐评内的当日听感注记

“当日听感注记”位于乐评正文之后、完整元数据之前。列表页只显示日期、日型、节日和天气的紧凑标签，避免卡片拥挤。

注记包含：

- 日期及工作日、调休工作日、普通假日或节假日。
- 节日标签。
- 当地天气背景。
- 当天乐评数量。
- 主要感受与最关注的音乐对象。
- 一条可回到原记录的代表原句。

只有精确 `listenedAt` 的记录显示注记。一天一篇乐评时分析当前乐评；一天多篇时生成共享的当日切片。当天数据按日期即时从乐评与缓存上下文计算，不为每篇乐评复制存储。

天气或节日仅作背景证据，不生成因果判断。天气缺失时隐藏天气信息，不显示错误占位，也不阻止乐评打开。

## 4. 日期、假期与节日

应用不读取手机系统日程，不申请日历读取权限，不访问会议、生日或提醒。

日期分类固定为：

- 工作日
  - 普通工作日
  - 调休工作日
- 假日
  - 普通假日，即周末
  - 节假日，即中国大陆官方放假日期

节日标签与日型独立，例如工作日的情人节、周末的圣诞节、春节放假日和周日调休工作日。

中国大陆放假与调休安排使用按年份打包、带来源与版本的官方数据。应用不在运行时抓取政府网页。缺少年份时只使用星期、周末和固定节日规则，绝不猜测调休。

首版国际节日包含情人节和圣诞节；中国传统及法定节日随官方年度数据标注。

## 5. 天气背景

用户在设置中手动选择常驻城市。应用只保存城市、国家/地区、时区和用于天气查询的粗略坐标，不持续定位，不读取 vivo 私有天气数据。

天气通过可替换的数据提供层按日期查询并缓存。第一版使用公开历史天气接口，保存日期、天气大类、最低/最高温、降水量和更新时间。天气大类归并为晴、多云/阴、雨和雪。

天气请求异步执行：

- 有缓存立即显示。
- 无缓存先显示不含天气的注记，再后台补全。
- 离线、超时、城市未设置或远端失败时保持核心功能可用。
- 乐评正文、标签、情绪和评分不会进入天气请求。

## 6. 月度听感总结

月度总结只分析当月 `song` 与 `album` 乐评。人工 `month` 记录作为“本月自述”单独呈现，可被用户阅读和引用，但不进入自动词频或关系分析。

月度作品包含：

1. 月度封面。
2. 本月主要感受。
3. 最关注的音乐对象。
4. 主要“对象 × 描述词”组合。
5. 本月表达方式。
6. 日期、节日与天气切片。
7. 代表性原句。
8. 本月自述。

数据量模式：

- 0 篇：不生成。
- 1 至 2 篇：生成月度记忆卡。
- 3 篇及以上：生成完整月度作品。

日期或天气的组间比较要求至少 6 个有效乐评日，且每个被比较组至少 2 个乐评日。单个节日可以作为“节日听感切片”展示，但不表述为规律。

## 7. 十二个月独立美术系统

每个月不是颜色换皮，而是一套独立构图、信息组件和动效语言：

1. 一月：霜刻唱片封套。
2. 二月：漆红方印。
3. 三月：植物标本页。
4. 四月：雨线蓝图。
5. 五月：日光剪纸。
6. 六月：水纹乐谱。
7. 七月：热浪胶片与大字排版。
8. 八月：夜航星图。
9. 九月：标本抽屉。
10. 十月：旅行票据。
11. 十一月：布面档案册。
12. 十二月：年末封缄信件。

分析逻辑跨月一致，美术主题决定内容的组织方式。例如三月把主词表现为植物标本、把对象表现为分类标签、把变化表现为生长轨迹、把原句表现为观察记录。

同一月份跨年保持稳定的艺术身份，但图形数量、疏密、尺寸、主色偏移和版面重心由当月结构化数据确定。动效仅用于翻页、线条绘制、印章显形和轻微纸张位移；遵循系统“减少动态效果”设置。

## 8. 年度私人听感标本册

年度章节按数据充分度动态出现：

1. 年度封面与听感题名。
2. 全年评价概览。
3. 年度语言标本。
4. 主要感受与审美词。
5. 最关注的音乐对象。
6. 对象与描述词组合。
7. 十二个月的变化轨迹。
8. 工作日、假日、天气与节日背景。
9. 表达方式变化。
10. 审美迁徙。
11. 年度代表原句。
12. 年度留声与结语。

审美迁徙展示新出现、持续出现、明显减少的词，以及关注对象和对象描述组合的变化。只描述数据关系，不解释为人格、心理状态或外部因素造成的结果。

年度数据模式：

- 0 篇：不生成。
- 1 至 2 篇：年度记忆卡。
- 3 至 7 篇：精简年鉴。
- 8 篇及以上：完整标本册。

日期或天气年度比较要求至少 12 个有效乐评日，且每个被比较组至少 4 个乐评日。月度轨迹要求至少 3 个有分析数据的月份。

年度封面依据数据确定性生成；抽象“听感印章”只作装饰，不承担未经说明的数据编码。所有统计图标明数值、单位和计算口径。

## 9. 防重复聚合

年度结果由十二个月的结构化快照与“只有年份、没有月份”的独立记录桶合并。原始乐评只用于生成缺失或过期的月份快照、建立原文证据和分析无月份记录。

如果年度生成时某个月没有快照或快照过期，系统自动补算；用户无需先逐月打开或生成。月度和年度生成文案都不进入语义分析。

## 10. 可解释性与用户校正

每个结论展示它回答的问题、主词、出现次数、乐评覆盖数、覆盖比例和原文证据。重要证据最多两步回到原乐评。

用户可以：

- 查看命中来自哪些原句。
- 更换系统选出的月度或年度代表原句。
- 排除错误命中。
- 把表达调整到正确类别。

校正记录保存在本地并随备份导出。校正后仅使受影响的日期、月份和年度结果失效。

## 11. 数据、兼容与失效

### 存储边界

- 保留现有 `ReviewEntry` 字段和读写行为。
- 保留 `YearlySummary.content`，旧总结继续使用现有 Markdown 阅读器。
- 新年度结果额外保存版本化结构快照、来源指纹和分析版本。
- 月度作品作为独立生成结果保存，不伪装为人工 `month` 乐评。
- 天气缓存、城市设置和本地语义校正独立保存。
- 结构快照只保存统计与展示所需证据句，不复制完整乐评正文。

### 备份兼容

v2.1.0 导出新的备份版本，并继续接受 v1、v2 备份。旧备份缺失分析、月度作品、天气、设置或校正时按空值处理。导入前快照、导入撤销、浏览器本地存储和 Android SQLite 保持同等行为。

### 失效规则

- 新增、编辑或删除乐评：使相关日期、月份和年度失效。
- 修改精确日期：同时影响旧日期、新日期、旧月份、新月份和年度。
- 修改本月自述：只刷新月度展示，不改变自动统计。
- 天气补全：只更新上下文展示与相关关系分析，不重跑正文语义。
- 节假日数据升级：重算相关日期分类与关系分析。
- 语义词典或规则升级：旧结果保留并提示“分析方法已更新”，由用户重新生成。

所有新结果完整生成并通过结构校验后才替换旧结果；失败时保留上一次成功结果。

## 12. 隐私、错误处理与性能

- 语义分析完全本地执行，不上传乐评正文。
- 不读取系统日历，不持续定位。
- 天气请求只包含粗略坐标、日期和必要查询参数。
- 数据不足时降级或隐藏章节，不制造趋势。
- 单句无法分析时跳过该句，不使整本总结失败。
- 不生成心理诊断、人格判断或天气/节日因果结论。
- 分析以正文总字符数线性扫描为目标；结果通过来源指纹复用。
- 长章节按需渲染，动画不同时启动，确保小屏 Android 流畅。

## 13. 交互、美术、验证与发布

### 人体操作逻辑

- 主要入口继续使用现有底部导航“总结”，不增加底部导航数量。
- 总结页先选择年份，再展示十二个月的紧凑入口和年度生成按钮。
- 月份入口使用至少 44×44 CSS 像素的点击区域；常用操作位于拇指容易触达的下半屏。
- 一个页面只保留一个主操作；生成、刷新、查看证据和返回原文有明确层级。
- 危险操作继续二次确认；生成与天气刷新不使用二次确认。
- 详情页内容顺序为音乐信息、乐评正文、当日听感注记、扩展元数据，避免背景信息压过正文。

### 清晰度

- 每页先说明回答的问题，再显示图形。
- 图形标明数值、单位和统计口径。
- 不使用无法解释的词云、抽象占比图或只有装饰没有信息的图表。
- 十二月主题可以丰富，但共享一致的信息层级、返回方式、证据面板和无障碍语义。
- 支持系统大字体、安全区、深浅文字对比和减少动态效果。

### 验证

至少覆盖：

- 同义词、最长匹配、否定、程度词、转折和对象描述配对。
- 出现次数、乐评覆盖、乐评日覆盖、月份覆盖分别计算。
- 日、月、年聚合不重复计数。
- 精确日期缺失、跨月移动和本月自述隔离。
- 工作日、周末、调休、节假日和独立节日标签。
- 城市未设置、天气缓存、离线、超时和远端失败。
- 三种月度/年度数据量模式及所有阈值边界。
- 十二套主题、小屏、大字体、横竖屏和减少动态效果。
- v1、v2 备份导入与 v2.1.0 备份完整恢复。
- 浏览器预览与 Android SQLite 结果一致。
- TypeScript、现有检查脚本、移动端生产构建和 Android debug APK 构建。

### 发布

1. 将应用版本更新为 `2.1.0`，Android `versionName` 同步为 `2.1.0`，`versionCode` 单调递增。
2. 更新 README 和发布说明，明确本地分析、天气联网范围、日历权限边界和备份兼容。
3. 逐项核对本方案十三部分及 v2.0.1 回归功能。
4. 仅在所有验证通过后提交 Git，推送到 GitHub，并发布带版本号的 release 产物。

## 成功标准

- v2.0.1 的现有功能和旧数据保持可用。
- 无需在线 AI 即可生成可解释的日、月、年听感结果。
- 每个重要结论能查看数值、口径和真实原句。
- 十二个月具有可辨识的独立主题，同时界面清晰、操作一致。
- 天气、节日与日期只作背景关系，不产生因果暗示。
- 备份、恢复、失效、离线和生成失败不会造成数据丢失。
- v2.1.0 通过全量检查、构建和 Android 真机可执行产物验证后发布到 GitHub。
