# 小懂哥 v1.0.3 可靠性重构设计

## 目标

修复 Android/mobile 与 Next.js/Prisma 桌面端在记录变更、年度总结、聚合展示和 Android 构建上的已确认问题；不改变记录字段、备份格式或用户界面流程。

## 范围

1. 记录创建、编辑、删除后，使受影响年份的已保存年度总结失效。
2. 桌面端专辑和歌曲聚合按实际 `createdAt` 选择最近记录。
3. mobile 原生 SQLite 初始化使用单一进行中的任务，避免并发调用重复建立连接或执行建表。
4. Android 构建脚本优先读取 `ANDROID_SDK_ROOT`、`ANDROID_HOME` 与 `JAVA_HOME`，仅在这些变量均未设置时保留当前本机路径作为兼容兜底。
5. 添加最小检查，固定上述代码路径和构建脚本的环境变量约定。

## 设计

### 年度总结失效

桌面端在同一数据库事务中完成记录变更与 `YearlySummary` 删除：

- 新建记录：删除新记录所属年份的总结。
- 编辑记录：删除编辑前与编辑后所属年份的总结；年份未变时只删除一次。
- 删除记录：删除被删记录所属年份的总结。

mobile `Store` 在完成记录变更后删除相应 `YearlySummary`。浏览器存储与原生 SQLite 各自通过既有存储路径执行，维持两端一致语义。

年度总结被删除后，用户需要显式重新生成；不在写入记录时自动生成，从而避免写入路径触发耗时操作或 OpenAI 调用。

### 聚合最近记录

桌面端 `getAlbumAggregates` 与 `getSongAggregates` 在每个分组内按 `createdAt` 降序选择最近记录。分组键、年份集合与 API 返回结构保持不变。

### mobile 初始化

`Store` 增加私有初始化任务。首次原生调用创建任务，后续并发调用复用同一任务；任务失败后清除引用，允许下一次调用重新初始化。浏览器路径继续直接返回。

### Android 构建环境

构建脚本按以下顺序确定路径：

1. Android SDK：`ANDROID_SDK_ROOT`，再 `ANDROID_HOME`，再现有本机路径。
2. JDK：`JAVA_HOME`，再现有本机路径。

脚本仍在路径不存在时停止并给出明确错误；Gradle 任务和 APK 输出位置不变。

## 验证

- 新增 Node 检查脚本，验证总结失效调用、按 `createdAt` 选取聚合记录、初始化任务以及 Android 环境变量优先级仍在源码中。
- 运行 `npm.cmd run typecheck`、现有所有 `mobile:check:*`、`npm.cmd run mobile:build`、`npm.cmd run build`。
- 运行 Android debug 构建；若本机 Android 工具链不可用，报告实际错误，不宣称 APK 已验证。

## 非目标

- 不拆分 `mobile/src/App.tsx`。
- 不迁移数据库 schema、备份版本或封面存储格式。
- 不改变 3D 场景的包拆分策略。
