# Android 封面清晰度保留

Yves 明确要求按最大能力保留原图清晰度，直接实施，不再以 512 像素和 JPEG 90 作为自动封面输出。保留并行会话已完成的 3.4.0(38) 公众号出稿及好友圈测试功能，在其基础上构建 3.4.1(39)，不提交、推送、公开发布、部署或操作个人手机/旧模拟器。

## 行为

- 只使用选中且正在播放的同一系统媒体会话；比较专辑图、媒体图、显示图及其可访问 URI，优先保留较大有效图片。尺寸相当时优先原文件字节；不擅自把缩略图称为高清原图。
- URI 原文件：验证可显示格式、图片头、尺寸和读取边界后保留原字节；临时采样解码仅验证图片可用，不用于输出。Bitmap：保持收到的尺寸和受支持的色彩精度，采用 PNG，不回收系统拥有的对象。限额为4MiB、20MP，Bitmap分配限80MB；超限跳过，不静默缩图或改为低清 JPEG。
- 保留隐私同意、通知使用权复查、受限单线程、有限等候、content/HTTPS URI 信任边界、禁止 file/HTTP/凭据/私网/不安全重定向等原有防护。保留合理体积与像素边界，慢 URI 不得使已经可用的同会话 Bitmap 消失或串给其他作品。
- 页面取消 512/1.4M 字符旧门槛，接受原尺寸图片；仍以已有手动封面优先并校验作品身份、请求 revision 和手动选图 revision。预览、草稿恢复、正式封面和完整备份必须保持像素/原字节；草稿空间不足沿用明确失败和离开保护，不能无声丢图或正文。
- 保持现有 SQLite 结构、JSON v6 和可覆盖升级身份。既有好友圈发布图片的重编码属于对外发布链路，不在本轮改动范围。旧封面不自动覆盖。

## 验收

URI 原图片的输入/输出 SHA-256 相同；Bitmap 大于512像素时仍维持原尺寸，PNG 解码后标准 ARGB 像素相同，透明度保留，系统 Bitmap 不回收。覆盖不同清晰度候选、原文件与 Bitmap 回退、无图/坏图、体积/像素/超时、慢提供者和隐私撤回。前端真实浏览器/SQLite 验证大图预览、草稿恢复、正式保存、完整及无图备份、手动封面/身份/切歌竞态。

尽可能使用项目独立 Android 测试运行时执行图像测试；不把普通 JUnit 或浏览器合成桥当作 Android 原生图像执行。无法执行的设备/色彩精度范围必须明确说明。真实播放器返回的图可能已由播放器或系统缩小，不能承诺取回未提供的高清源文件。
