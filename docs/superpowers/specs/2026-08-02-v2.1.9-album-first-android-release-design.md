# v2.1.9「专辑优先」Android 记录与发布设计

## 1. 背景

v2.1.8 已具备快速记录、完整乐评、当前播放读取、Apple 音乐目录补全、专辑与歌曲聚合、重听、SQLite v5 备份和 Android APK 构建。实际使用以 Android App 和专辑感受记录为主，但当前默认流程仍以歌曲为中心：完整表单默认 `song`，快速记录固定保存歌曲，底部主导航没有专辑入口。

v2.1.9 同时完成四类工作：

1. 修复 v2.1.8 审查中的隐私、发布、弹层和损坏存储问题，并补充端到端检查。
2. 把快速记录压缩成真正的一屏主流程，并接入 Android 系统分享。
3. 建立必须签名、签名后校验的 release APK 发布链。
4. 将记录、识别、导航、重复检测和统计入口调整为专辑优先。

版本主题为：

> v2.1.9「专辑优先」
>
> 从正在播放的一首歌，回到整张专辑的感受。

## 2. 目标

1. Android 用户从音乐 App 分享文本到小懂哥后直接进入快速记录，并立即尝试读取当前媒体会话。
2. 识别到所属专辑时，快速记录和完整记录默认创建专辑档案。
3. 专辑记录不混入歌曲统计；当前歌曲仅作为识别来源保留在 `MusicMetadata`。
4. 快速记录首屏只保留专辑身份、一句话、日期和保存，评分与情绪默认折叠。
5. 底部主导航提供专辑入口，时间轴移动到“更多”。
6. Android 系统云备份不复制私人档案；用户通过应用内备份控制数据去向。
7. release 构建没有长期签名配置时明确失败，签名和版本校验通过后才输出发布 APK。
8. 备份页能够显示上次成功保存、数据数量、文件大小、SHA-256 和当前可恢复性检查结果。

## 3. 非目标

v2.1.9 不包含：

- 新增专辑与曲目关系表。
- 把每首歌曲改造成专辑的子记录。
- 猜测网易云、QQ 音乐、Apple Music 等分享文本的私有格式。
- 从分享链接抓取网页、歌词或音频。
- 自动创建记录；用户仍需写下一句话并点击保存。
- 自动云同步、自动上传备份或托管签名密钥。
- 自动生成或替换长期 Android keystore。
- 对整个 `App.tsx`、`store.ts` 或旧版 Next.js 端进行无关重构。

## 4. 专辑优先数据语义

### 4.1 识别结果转换

当前播放、Apple 目录补全、截图识别和 Android 分享进入同一套专辑优先转换规则：

1. 有有效 `albumName`：
   - `type = "album"`
   - `title = albumName`
   - `albumName = albumName`
   - `artistName = albumArtistName ?? artistName`
   - `songName = null`
2. 没有专辑但有歌曲：
   - `type = "song"`
   - `title = songName`
   - `songName = songName`
3. 两者都没有：只展示分享原文或手动填写入口，不补造字段。

识别来源歌曲继续保留在 `MusicMetadata.displayTitle`、`catalogTrackId`、`trackNumber` 等字段中；转换时如果原始元数据没有 `displayTitle`，必须用已确认的歌曲名补入。专辑记录页面可显示“从歌曲《X》识别”，但不得把该值写入 `ReviewEntry.songName`，否则会进入歌曲聚合和歌曲统计。

### 4.2 专辑身份匹配

专辑重复检测顺序固定为：

1. 双方都有 `catalogAlbumId` 且完全一致，视为同一专辑。
2. 否则要求规范化后的 `albumName` 与 `artistName` 都完全一致。
3. 缺少艺术家时不自动判定为同一专辑。
4. 只有标题或只有专辑名时不自动合并。

规范化沿用 Unicode NFKC、大小写不敏感、连续空白压缩和首尾空白移除。

快速保存命中已有专辑时，提供两个明确选项：

- 进入现有专辑档案并追加听感。
- 仍然新建另一篇专辑记录。

### 4.3 兼容性

继续使用现有 `ReviewEntry`、`ListeningMoment`、`MusicMetadata` 和 `AppData`，不新增 SQLite 表或列，不提高 v5 备份版本。旧歌曲记录、旧专辑记录和旧草稿保持原样，不批量转换。

## 5. 完整记录

### 5.1 默认值

直接打开 `/new` 时：

- 记录类型默认“专辑”。
- 页面标题改为“记录专辑感受”。
- 当前播放识别到专辑后，标题默认使用专辑名。
- 当前播放只有歌曲信息时回退为歌曲记录。
- 用户仍可手动切换记录类型并编辑全部字段。

### 5.2 专辑优先填充

正式表单的当前播放和 Apple 补全结果先经过专辑优先转换，再执行“只填空白字段”。已存在的草稿或编辑中的记录不被自动改类型，也不覆盖已有音乐身份。

截图识别明确识别为专辑时沿用专辑结果；识别为歌曲但同时识别出专辑时同样转换为专辑默认。用户手动选择歌曲后不再自动改回专辑。

## 6. 一屏快速记录

### 6.1 主流程顺序

快速记录页面首屏顺序调整为：

1. 专辑卡片：封面、专辑名、艺术家、识别来源歌曲。
2. 一句话感受，必填。
3. 感受日期，默认今天。
4. 保存专辑速记。
5. “补充评分、情绪和音乐信息”折叠区。
6. 展开完整专辑乐评。

评分、评分修饰符、最近情绪、全部情绪和手动音乐身份默认折叠。折叠只改变布局，不改变草稿或保存数据。

### 6.2 保存

有专辑身份时快速记录创建 `type=album` 的 `ReviewEntry`；没有专辑时使用歌曲回退。保存前使用对应的专辑或歌曲身份匹配器检查重复。

快速草稿继续使用 `EntryDraft version=2` 和 `captureMode=quick`。草稿中的 `type` 保存实际模式，旧快速草稿中的 `song` 保持歌曲语义，不自动转换。

## 7. Android 系统分享入口

### 7.1 Manifest

`MainActivity` 增加 `ACTION_SEND + CATEGORY_DEFAULT + text/plain` intent filter。应用只出现在文本分享列表，不声明所有 HTTP/HTTPS 链接的默认打开能力。

### 7.2 原生插件

新增本地 Capacitor 插件 `SharedMusicPlugin`：

- 冷启动通过 `BridgeActivity` 已有的 `onNewIntent(getIntent())` 收到分享 Intent。
- 热启动覆盖 `Plugin.handleOnNewIntent(Intent)`，收到新分享时通知 JS 监听器。
- 只读取 `Intent.EXTRA_TEXT` 和 `Intent.EXTRA_SUBJECT`。
- 对文本做长度上限和空白清理，不读取附件、不访问分享来源应用的数据。
- 提供 `consumePendingShare()`；成功消费后清除内存中的待处理值，避免刷新重复打开。

### 7.3 Web 路由

App 壳层注册一次分享监听：

1. 收到分享时把精简后的 subject/text 放入 `sessionStorage`。
2. 导航到 `/capture?source=share`。
3. 快速记录页显示“来自 Android 分享”的只读提示。
4. 页面调用现有 `NowPlaying.getCurrentTrack()`，再走 Apple 目录补全和专辑优先转换。

分享文本不直接猜测歌曲、歌手或专辑字段。当前媒体会话不可用时保留分享原文供用户参考，并允许手动填写。未来只有在取得真实分享样本后才增加来源应用专用解析器。

## 8. 专辑优先导航与呈现

- 底部导航改为：首页、专辑、新建、搜索、总结。
- 时间轴入口移动到“更多”，不删除功能。
- 首页主按钮文案改为“快速记下专辑”和“写专辑感受”。
- 新建选择中的正式记录描述强调“从当前歌曲识别所属专辑”。
- 专辑列表沿用现有 `albumAggregates()`，不新增重复页面。
- 歌曲列表保留在“更多”，用于旧歌曲记录和无法识别专辑时的回退记录。

## 9. v2.1.8 审查修复

### 9.1 私人数据系统备份

Android Manifest 将 `android:allowBackup` 改为 `false`。v2.1.9 不依赖系统云备份，唯一明确的数据迁移通道是应用内 JSON 备份。

### 9.2 BottomSheet

通用 `BottomSheet` 统一支持：

- 使用按钮而不是 `href="#"` 打开。
- 打开后聚焦首个可操作元素。
- Tab/Shift+Tab 焦点保持在弹层内。
- Esc 关闭。
- Android/浏览器返回或路由变化关闭。
- 关闭后焦点返回触发按钮。
- 弹层打开时背景内容设为 `inert`；不支持 `inert` 的环境至少依赖焦点陷阱和 `aria-modal`。

### 9.3 损坏 Web 存储

主存储 JSON 解析失败时：

1. 原始字符串移动到固定隔离键。
2. 原主键删除，防止后续写入覆盖损坏原文。
3. 写入可读的损坏通知。
4. 当前读取抛出错误，不静默伪装成空档案。
5. 备份页显示隔离数据存在，并允许复制原始内容；用户明确清除前不删除。

隔离键固定复用，避免同一损坏值重复占用 localStorage。

### 9.4 v2.1.8 端到端测试

新增 Playwright 端到端脚本，使用本机 Chrome，覆盖：

- 首页底部新建按钮打开选择弹层。
- 焦点进入弹层。
- Esc 关闭并恢复焦点。
- 速记和正式记录分别进入正确路由。
- 页面无控制台错误或未处理异常。

测试使用临时浏览器上下文，不读取或修改真实手机数据。

## 10. 备份健康中心

### 10.1 健康记录

备份健康状态写入现有 `AppData`，包含：

- 上次内部验证时间。
- 上次成功保存文件时间。
- 文件名。
- UTF-8 字节数。
- SHA-256。
- entry、summary、monthlySummary、cover、listeningMoment 数量。
- 备份 schema 版本。

健康状态随 v5 备份导出和恢复，不新增表。

### 10.2 检查流程

“检查当前备份能力”执行：

1. 调用 `exportBackup()` 生成当前 JSON。
2. 调用 `previewBackup()` 重新解析并完成结构校验。
3. 比较导出前后的记录数量。
4. 使用 Web Crypto 计算 SHA-256。
5. 全部成功后记录“当前数据可生成并重新解析”。

该检查不覆盖当前数据，也不执行破坏性恢复。只有 `Filesystem.writeFile()` 成功后才记录“已保存文件”；仅生成 JSON 不算完成备份。

### 10.3 页面

备份页顶部显示：

- 当前状态：未检查、检查通过、检查失败。
- 上次成功保存时间与文件名。
- 数据数量与文件大小。
- SHA-256 短摘要，可展开复制完整值。
- “立即检查”和“导出 JSON”操作。

## 11. 签名 APK 发布链

### 11.1 私密配置

仓库不提交 keystore 或密码。release 构建从以下环境变量读取：

- `XIAODONGGE_KEYSTORE_FILE`
- `XIAODONGGE_KEYSTORE_PASSWORD`
- `XIAODONGGE_KEY_ALIAS`
- `XIAODONGGE_KEY_PASSWORD`

缺少任一值、文件不存在或签名失败时，release 脚本立即失败。

### 11.2 构建和验证

release 脚本固定执行：

1. Vite 移动端生产构建。
2. Capacitor Android sync。
3. Gradle `assembleRelease`，输出已签名 APK。
4. `apksigner verify --verbose --print-certs`。
5. `aapt2 dump badging`，核对包名、`versionName=2.1.9` 和 `versionCode=12`。
6. 计算 SHA-256。
7. 复制到 `release/xiaodongge-v2.1.9.apk`。

脚本不得把 `app-release-unsigned.apk` 报告为成功产物。

### 11.3 密钥边界

本版本只建立接入和校验链，不生成长期密钥。实际发布前由用户提供原来用于可升级安装的同一 keystore；如果不存在旧密钥，只能建立新的签名身份，旧安装包将无法覆盖升级。

## 12. 错误与降级

- 分享文本为空：不导航，原生调用返回明确错误。
- 分享文本过长：截断到固定上限，并标记已截断。
- 当前播放权限关闭：显示授权入口和分享原文，允许手填。
- 当前播放无专辑：回退歌曲记录，不制造专辑名。
- Apple 目录失败：保留原生媒体会话字段。
- 专辑身份出现多个匹配：要求用户选择，不自动合并。
- 备份检查失败：不更新上次成功状态，显示失败阶段。
- 文件写入失败：不记录“已保存”。
- keystore 配置缺失或签名验证失败：不输出 release 成功信息。
- Web 存储损坏：保留隔离原文并阻止静默覆盖。

## 15. 成功标准

- 从 Android 音乐 App 分享文本能够稳定进入小懂哥快速记录，冷启动和热启动不重复消费。
- 当前歌曲有专辑信息时，快速和完整记录默认生成干净的专辑记录，并且歌曲聚合不会出现该专辑记录。
- 用户能在首屏写一句话并保存，不必先操作评分、情绪或完整音乐字段。
- 首页和底部导航明显以专辑为主，旧歌曲和时间轴功能仍可到达。
- 四项审查问题都有自动检查或可重复验证证据。
- 备份页能证明当前数据可导出、可重新解析，并准确记录实际文件保存状态。
- 没有签名密钥时 release 明确失败；有正确密钥时只输出签名验证通过的 `v2.1.9` APK。
