# 当前播放元数据联网补全设计

## 目标

Android 用户授予通知使用权后，打开“新建记录”页面即可自动识别网易云音乐当前播放内容，并在无需账号、API Key 或额外操作的前提下联网补全可可靠匹配的音乐元数据。识别结果必须进入自动草稿、正式记录、详情展示和备份恢复链路。

支持 Android 7.0（API 24）及以上。当前播放读取或联网补全失败时，用户仍可正常手工填写、使用截图识别和保存记录。

## 范围

### 包含

- Android `MediaSession` 公开的当前播放元数据。
- Apple iTunes Search API 中国区目录查询；中国区无可靠结果时查询美国区。
- 原生元数据与目录结果的保守合并。
- 元数据的草稿保存、SQLite 持久化、详情展示及 JSON 备份导入导出。
- 对旧数据库、旧草稿和版本 1 备份的向后兼容。
- 联网失败、无结果和结果不明确时的离线降级与手动重试。

### 不包含

- 歌词、音频、试听文件、价格、播放历史或其他通知正文。
- 网易云音乐账号登录、Cookie、内部接口或逆向协议。
- Spotify、MusicBrainz 或自建聚合后端。
- 自动创建正式记录；正式记录仍由用户点击“保存”后写入。
- 自动下载或持久化第三方目录提供的宣传图片。

## 数据来源与优先级

### 1. Android 媒体会话

现有 `NowPlayingPlugin` 继续通过已授权的 `NotificationListenerService` 获取正在播放的活动媒体会话。插件读取以下可序列化字段；没有提供的字段保持为空：

- 标题、展示标题
- 艺术家、专辑、专辑艺人
- 作者、词作者、作曲者、合辑信息
- 创建或发行日期、年份、流派
- 时长、曲目序号、曲目总数、碟片序号
- 媒体 ID、媒体 URI、封面 URI
- 展示副标题、展示描述
- 来源应用包名

不序列化 `Bitmap`、`Rating` 或未知对象。媒体会话提供的值优先级最高，联网结果不得覆盖非空原生值。

### 2. Apple 音乐目录

当原生结果至少包含歌曲名和歌手时，原生插件使用 HTTPS 查询 iTunes Search API：

1. 以 `country=CN`、`media=music`、`entity=song` 查询有限数量结果。
2. 中国区没有可靠匹配时，以相同条件查询 `country=US`。
3. 每次“读取当前播放”最多执行这两次目录请求，不分页。

目录用于补充：专辑、发行日期、流派、时长、曲目与碟片序号及总数、明确内容标记、Apple 艺术家/专辑/歌曲 ID。目录返回的价格、币种、试听地址和宣传图片不保存。

查询请求只包含歌曲名、歌手和已有专辑，不发送正文、情绪、标签、评分、其他通知或已有日记数据。

## 匹配规则

目录结果先进行 Unicode 规范化、大小写折叠、连续空白合并和首尾标点清理，然后计算匹配：

- 歌曲名必须规范化后完全相同。
- 歌手必须规范化后完全相同，或目录歌手列表明确包含原生歌手。
- 原生结果已有专辑时，完全相同的专辑优先。
- 多条结果仍无法区分时，不自动补全。

不使用模糊标题替换，不依据热度选择，不把重制版、现场版或伴奏版自动当作原曲。所有联网字段保存来源和补全时间，详情页将发行日期标为“目录发行日期”，避免把地区上架日期解释为作品首次发行日期。

## 数据模型

现有 `songName`、`artistName` 和 `albumName` 字段保持不变，继续服务搜索、聚合和年度统计。`ReviewEntry` 新增一个可空的结构化 `musicMetadata` 对象，并在 SQLite 中使用一个可空 JSON 文本列持久化，避免为只读补充字段建立大量列。

`musicMetadata` 包含以下稳定字段：

- `albumArtistName`
- `authorName`
- `writerName`
- `composerName`
- `compilation`
- `releaseDate`
- `releaseYear`
- `genre`
- `durationMs`
- `trackNumber`
- `trackCount`
- `discNumber`
- `discCount`
- `explicitness`
- `mediaId`
- `mediaUri`
- `artworkUri`
- `displayTitle`
- `displaySubtitle`
- `displayDescription`
- `sourcePackage`
- `catalogSource`
- `catalogTrackId`
- `catalogAlbumId`
- `catalogArtistId`
- `enrichedAt`

所有字段均可空。Apple 日期保存为目录返回的 ISO 日期，Android 原生日期保存为经过首尾空白清理的原始文本；`releaseYear`、时长和序号保存为非负整数。枚举、字符串和数值在原生边界与备份导入边界验证。

数据库初始化时检查 `ReviewEntry` 是否已有元数据列；缺少时只执行一次加列迁移。旧记录读取为 `musicMetadata: null`，不重写其他数据。

## 用户流程

1. 用户打开 Android 新建记录页。
2. 草稿恢复完成后，应用自动读取当前播放。
3. 原生结果立即填入当前为空的歌曲、歌手、专辑和标题字段。
4. 有歌曲名和歌手时，状态显示“正在联网补全”，随后合并可靠目录结果。
5. 识别区展示歌曲、歌手、专辑、发行日期和流派摘要，并提供“更多音乐信息”展开区。
6. 表单、识别结果和完整元数据一起进入现有自动草稿。
7. 用户点击保存后，完整元数据写入正式记录；详情页展示所有非空字段及数据来源。

编辑已有记录时不自动读取当前播放，避免覆盖历史内容。联网补全只填空字段；用户已填写的歌曲、歌手、专辑和标题不会被覆盖。

## 网络与权限

- Manifest 明确声明 `android.permission.INTERNET`；该权限无需运行时授权弹窗。
- 通知使用权仍是唯一需要用户进入系统设置授予的特殊权限。
- HTTPS 请求在原生插件的后台执行，不阻塞主线程，也不受 WebView CORS 限制。
- 连接超时为 5 秒，读取超时为 8 秒；失败后不自动循环重试。
- 页面提供“重新联网补全”，用户主动点击时重新执行一次当前播放读取和目录查询。

## 错误处理

- 未授权：显示通知使用权说明和系统设置入口。
- 无正在播放会话：保持表单不变并提示重试。
- 原生字段不完整：保留已读字段；只有歌曲名和歌手齐全时才联网。
- 网络超时、无网络、HTTP 错误或响应格式异常：保留原生结果，显示“联网补全失败，可重试”。
- 无可靠匹配：显示“未找到可确认的目录信息”，不填入任何目录字段。
- SQLite 迁移失败：停止数据库打开并显示明确错误，避免在部分迁移状态下写入。
- 草稿或备份中的元数据格式无效：拒绝该元数据对象，不执行不受验证的数据库写入。

## 草稿与备份兼容

- 草稿格式升级为版本 2，同时继续接受版本 1 草稿；版本 1 缺少元数据时按 `null` 处理。
- JSON 备份升级为版本 2，同时继续接受版本 1 备份；版本 2 导出包含 `musicMetadata`。
- 导入前快照、导入撤销和正式导入都必须保留完整元数据。
- TXT 与 CSV 导出追加常用字段：发行日期、流派、时长和来源；完整结构仍以 JSON 备份为准。

## 隐私与上架要求

- 首次联网补全前的界面说明：应用会把当前歌曲名、歌手和专辑发送给 Apple 音乐目录以补全信息。
- 隐私政策列明数据接收方、发送字段、使用目的及联网失败的离线行为。
- 不上传日记正文、标签、情绪、评分、设备通知正文或历史数据库。
- 不内置第三方账号凭据，不使用非公开网易云接口，不持久化 Apple 试听或宣传内容。

## 验证

最小可运行检查覆盖：

1. 原生媒体元数据到 JavaScript 结果的类型转换。
2. 中国区可靠结果、美国区回退、无结果和多结果不明确的匹配行为。
3. 原生字段优先、目录只补空字段。
4. 网络超时和异常响应的离线降级。
5. SQLite 旧库加列迁移及迁移后读写。
6. 新旧草稿恢复和新旧 JSON 备份导入。
7. 详情页及 TXT、CSV、JSON 导出中的元数据。
8. TypeScript 检查、移动端构建、现有可靠性检查和 Android debug APK 构建。

实机验收使用网易云音乐 9.5.60：播放歌曲后打开新建页，无需额外输入即可看到当前播放摘要；目录存在可靠匹配时显示发行日期等补充信息；断网时仍能保存原生识别结果。

## 成功标准

- Android 7.0 及以上 APK 可以完成自动识别和联网补全。
- 除首次通知使用权授权外，正常流程不要求额外设置、账号或密钥。
- 可靠匹配时，目录补充字段随草稿、记录和备份长期保留。
- 不可靠匹配或网络失败时不写入错误元数据，也不阻止用户记录。
- 现有记录、旧草稿、旧备份、截图识别和手工填写流程保持可用。
