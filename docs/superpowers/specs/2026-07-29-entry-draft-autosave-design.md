# 表单草稿自动保存设计

## 目标

让移动端的新建记录和编辑记录页面具备手机备忘录式的草稿体验。用户输入正文或修改其他信息后，应用自动将未正式提交的内容保存在本机。用户误退出、切到后台或结束应用后，再次进入对应页面可以恢复并继续编辑。

自动保存只写入后台草稿。新建草稿不会提前出现在正式记录列表中，编辑草稿不会在用户点击“保存”前更新正式记录。正式保存成功后删除对应草稿。

## 范围

草稿覆盖：

- 记录类型、标题、年份、月份
- 专辑、歌曲、艺术家
- 听歌或感受日期
- 曲风、自由标签、情绪、评分
- 正文
- 已选择并处理后的封面数据
- OCR 识别文本
- OCR 可编辑识别字段
- 最后保存时间

草稿不保存 OCR 原始截图文件。

首版只保存一份新建记录草稿。编辑已有记录时，每个记录 ID 保存一份独立草稿。首版不提供草稿列表。

## 存储方案

使用项目现有 WebView `localStorage` 保存版本化 JSON 草稿，不增加依赖或 SQLite 数据表。

草稿按用途使用独立键：

- 新建记录使用固定键。
- 编辑记录使用包含现有记录 ID 的键。

草稿数据包含结构版本、页面模式、记录 ID、正式记录基准更新时间、表单字段、选择状态、封面、OCR 状态和草稿保存时间。读取时严格校验边界数据，格式无效的草稿不得写入表单。

封面只在封面发生变化时更新草稿状态。普通文字输入的延迟保存不得反复重新处理图片。

## 页面数据流

### 新建记录

1. 渲染新建表单的默认值。
2. 读取并校验新建草稿。
3. 存在有效草稿时恢复全部字段、选择状态、封面和 OCR 状态。
4. 草稿恢复完成后再读取当前播放；当前播放只能填充空白字段。
5. 用户输入或其他页面操作修改数据后安排自动保存。

### 编辑已有记录

1. 从正式存储加载记录。
2. 渲染正式记录内容。
3. 读取该记录 ID 对应的草稿。
4. 草稿有效且不比正式记录旧时恢复草稿。
5. 正式记录更新时间晚于草稿基准时，不自动用旧草稿覆盖正式内容，并显示说明。

### 正式保存

1. 提交开始时立即补写一次最新草稿。
2. 沿用现有表单校验和重复记录确认。
3. 草稿包含新封面时先写入按音乐信息索引的本地封面，再写入正式记录；重复执行封面写入不会创建重复记录。
4. 正式记录成功写入后删除对应草稿并导航到记录详情。
5. 封面或正式记录保存失败时停留在当前页面，保留草稿和当前表单内容，允许用户重试。

## 自动保存触发

- 表单输入或选择变化后约 300 毫秒保存。
- 曲风、情绪、封面、OCR 状态变化时保存。
- 当前播放或 OCR 将数据应用到表单后保存。
- 页面触发 `visibilitychange`、`pagehide` 或组件卸载前补写最新状态。

同一个页面只允许一个待执行的延迟保存，后续输入替换前一次计划，避免无效重复写入。

## 使用体验

- 表单底部显示“正在保存草稿”或“草稿已自动保存 HH:mm”。
- 恢复成功后显示“已恢复上次草稿”。
- 状态区域使用无障碍实时提示，不使用弹窗打断输入。
- 存在草稿时提供“放弃草稿”。用户确认后才清除草稿，并恢复正式记录或新建默认表单。
- 正式保存按钮继续保留，用于把后台草稿转换为正式记录。

## 错误处理与数据安全

- `localStorage` 解析、校验或写入错误必须被捕获。
- 写入失败时保留页面中的当前内容，显示“草稿保存失败”，不得显示成功状态。
- 格式损坏的草稿不覆盖表单，也不自动删除，用户可通过“放弃草稿”清理。
- 正式记录比编辑草稿更新时不自动恢复旧草稿。
- 草稿只保存在本机，不上传、不记录埋点、不包含 OCR 原始截图。
- 放弃草稿属于破坏性操作，必须进行二次确认。

## 组件边界

- `mobile/src/entryDraft.ts`：定义草稿结构、校验、读取、写入和删除。
- `EntryFormPage`：采集页面状态、安排自动保存、恢复草稿、显示状态并处理放弃草稿。
- 现有 `store`：继续只负责正式记录、年度总结和封面持久化，不承担未完成草稿。

草稿模块不依赖 React，便于通过最小 Node 脚本验证。页面继续复用现有表单、OCR、当前播放、封面处理和正式保存流程。

## 验证

自动检查覆盖：

- 新建与编辑草稿键隔离
- 有效草稿的序列化和恢复
- 损坏 JSON、错误字段类型和未知结构版本
- 编辑草稿与正式记录更新时间冲突
- OCR 结果和封面字段的保留
- 正式保存后清除草稿的代码路径
- 当前播放在草稿恢复后只填空字段

回归命令覆盖 TypeScript、现有移动端专项检查、移动端生产构建、桌面生产构建和 Android debug APK 构建。

真机验收步骤：

1. 新建记录并输入正文及其他信息。
2. 等待“草稿已自动保存”。
3. 结束应用后重新打开新建页，确认全部草稿恢复。
4. 继续修改并重复恢复验证。
5. 编辑一条已有记录，重复退出和恢复验证。
6. 正式保存，确认对应旧草稿不再恢复。
7. 选择封面并执行 OCR，确认恢复识别文本、识别字段和处理后封面，不恢复原始截图。

## 发布边界

本功能按上架应用的数据安全、生命周期、可访问状态提示和错误反馈要求实现。商店签名、隐私政策、正式发布材料和商店审核提交属于发布阶段，不在本功能范围内。
