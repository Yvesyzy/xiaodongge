# v2.1.7「再次听见」A+ 设计方案

## 1. 背景

v2.1.6 已具备本地音乐感受记录、当前播放读取、Apple 音乐元数据补全、草稿箱、追加听感、多维度评分、情绪洞察、抽象地图、月度与年度作品、SQLite 存储及完整备份。

当前能力覆盖了“记录”和“分析”，但主流程仍以创建单篇乐评为中心。追加听感藏在记录详情页，旧记录不会主动回到首页，当前播放、草稿、追加听感和导出作品之间也没有形成连续旅程。

v2.1.7 以 A 方案的长期闭环为主体，吸收 B 方案中低摩擦记录能力，形成以下链路：

~~~text
当前正在听
  -> 快速记下或完整乐评
  -> ReviewEntry 私人档案
  -> 首页“今日重逢”
  -> 盲听重评
  -> ListeningMoment
  -> 事实型变化揭晓
  -> 本地记忆卡片
~~~

版本主题为：

> v2.1.7「再次听见」
>
> 快速记下这一刻，在下一次听见时看见变化。

## 2. 目标

1. 用户在 30 至 60 秒内完成一条有效音乐感受记录。
2. 当前播放歌曲已有档案时，引导用户追加听感，同时保留创建独立新乐评的明确选择。
3. 首页每天稳定展示一条值得重听的旧记录，建立回看理由。
4. 用户在看不到旧评价的前提下重新评分和记录情绪，提交后再查看事实变化。
5. 用户能够把单次快速记录或两次听感对比保存为本地图片。
6. 全程保持本地优先，不上传乐评正文、评分、情绪或播放历史。
7. 复用现有数据模型，避免为本版本新增 SQLite 表。

## 3. 非目标

v2.1.7 不包含：

- Android 桌面快捷方式或通知栏快速记录按钮。
- 语音输入、歌词抓取、音频识别。
- 在线 AI 生成、改写或总结用户感受。
- 自动选择情绪、自动继承评分或自动创建记录。
- 用户自定义记录模板。
- 独立于草稿箱的“未完成记录收件箱”。
- 追加听感的制作、词曲、原创性、共鸣四维评分。
- 多套分享卡视觉主题。
- 在线账号、云同步、社区和关注关系。
- 根据评分或情绪推断人格、心理状态或外部因果。
- 对整个 App.tsx 或 store.ts 进行与本版本无关的全面重构。

## 4. 产品结构

首页主操作提供三个入口：

1. 快速记下：短表单，创建 ReviewEntry。
2. 完整乐评：进入现有完整表单，创建 ReviewEntry。
3. 再次听见：选择已有 ReviewEntry，创建 ListeningMoment。

快速记录与完整乐评共享同一份 EntryInput 规则。快速记录不是新的记录类型，完整乐评也不因入口变化而改变现有数据。

再次听见只创建 ListeningMoment，不复制 ReviewEntry，不修改首次评分和首次正文。

## 5. 当前播放与音乐身份匹配

### 5.1 读取时机

现有原生桥接只提供主动读取当前播放快照，不提供歌曲变化事件。v2.1.7 固定在以下时机读取：

- 打开快速记录页时。
- 用户点击“重新读取当前播放”时。
- 快速记录页从后台重新变为可见时。

页面保持可见时不轮询，不增加持续后台监听。

### 5.2 写作中的歌曲变化保护

重新读取发现歌曲发生变化时：

- 表单没有用户输入：允许用新歌曲替换当前预填。
- 表单已有用户输入：不覆盖任何字段，显示非阻塞提示。

提示提供：

- 继续当前记录。
- 保存当前草稿，并为新歌曲创建快速草稿。

选择第二项时，必须先确认当前草稿写入成功；保存失败则停留在原页面并显示错误，不创建第二份草稿。

### 5.3 严格身份匹配

当前 entryDuplicate 的重复检测包含年份、月份和收听日期，不适合判断“这首歌是否已经有档案”。v2.1.7 新增独立的音乐身份匹配规则。

匹配顺序：

1. 双方都有 Apple catalogTrackId 且完全一致，视为同一首歌。
2. 否则要求规范化后的 songName 与 artistName 都完全一致。
3. 双方 albumName 都存在时还必须完全一致；任一方缺失专辑时不因专辑缺失否决。
4. 只有标题、只有歌曲名、只有专辑名或只有歌手时，不自动匹配。

结果处理：

- 恰好一个匹配：展示“再次听见”和“新建另一篇乐评”。
- 多个匹配：展示已有记录选择列表，不自动选择。
- 没有匹配：推荐快速记下，同时保留完整乐评入口。

所有文本规范化沿用项目现有的 Unicode NFKC、空白压缩和大小写不敏感原则。

## 6. 快速记录

### 6.1 页面内容

快速记录采用单屏主流程，字段顺序为：

1. 当前歌曲卡片。
2. 综合评分。
3. 常用情绪。
4. 一句话感受。
5. 收听日期。
6. 保存。
7. 展开完整乐评。

当前歌曲卡片显示封面、歌曲、歌手、专辑和信息来源。修改音乐身份字段的入口默认收起。

### 6.2 最低保存条件

快速记录创建正式 ReviewEntry 时必须满足现有记录校验：

- title 非空；当前播放有 songName 时，title 与 songName 使用同一已确认值。
- content 非空。
- year 使用收听日期对应的本地年份。
- month 使用收听日期对应的本地月份。
- listenedAt 使用用户选定日期的本地日期语义。
- type 固定为 song。

歌手、专辑、评分、情绪和封面允许为空。应用不得补造缺失信息。

### 6.3 最近使用情绪

快速记录显示最多 6 个最近使用情绪：

- 数据来自最近正式保存的 ReviewEntry。
- 按最近使用时间排序，同一情绪只出现一次。
- 不读取草稿，避免未完成内容影响快捷区。
- 只显示现有情绪词库中的值。
- 仅作为快捷按钮，默认不选中。

完整情绪选择器继续使用现有分类和词库。

### 6.4 草稿

快速记录复用 EntryDraft：

- 输入开始后参与现有自动保存。
- 草稿新增 captureMode 字段，值固定为 quick 或 full。
- 快速草稿在草稿箱标记为“快速记录”。
- 打开快速草稿返回快速页面。
- 选择“展开完整乐评”后，当前草稿转换为完整模式并进入完整表单。
- 转换过程中所有已有字段保持不变。
- 旧草稿缺少 captureMode 时按 full 读取。

不新增第二套草稿键空间，不新增独立收件箱。

### 6.5 保存结果

保存成功后进入记录详情页，并提供：

- 查看完整记录。
- 保存快速记录卡。
- 返回首页。

创建记录、封面保存或草稿清理任一步失败时，遵循现有数据安全顺序：正式记录成功后不得因为草稿清理失败而报告“记录未保存”；草稿清理失败单独提示。

## 7. 今日重逢

### 7.1 展示位置

首页在主操作区与“可视化记忆”之间显示“今日重逢”。无合格记录时完全隐藏该区域。

### 7.2 合格条件

记录必须满足：

- type 为 song。
- 有 songName。
- 有可解析的 listenedAt；若 listenedAt 缺失，不使用 createdAt 代替。
- 距今天至少 30 个本地自然日。
- 最近 30 个本地自然日内没有 ListeningMoment。

### 7.3 确定性排序

每条合格记录计算以下优先级，按顺序比较：

1. 周年窗口：距离任一完整周年的日期差不超过 7 天。
2. 长期未重听：距离最近一次收听至少 90 天。
3. 高评分：rating 较高优先；无评分排在有评分之后。
4. 更久未出现：最近一次 ReviewEntry 或 ListeningMoment 日期更早者优先。
5. 稳定顺序：最后按 entry id 排序。

同一天选择结果写入 AppData，因此当天新增或编辑其他记录时不切换卡片；以下情况例外：

- 对应 ReviewEntry 被删除。
- 对应记录不再是 song。
- 用户当天已经为它创建 ListeningMoment。

例外发生后重新计算一次；仍无结果则隐藏。

### 7.4 当天状态

AppData 保存：

- 本地日期。
- entry id。
- 是否已隐藏。

该状态固定使用 daily-resurfacing 键，只保存引用，不保存记录副本。跨入新的本地日期后重新计算。

用户点击“今天不想看”只隐藏当天卡片。下一天仍可按正常规则重新参与。

### 7.5 与当前播放合并

首页主动读取到当前播放，且严格身份匹配到今日重逢记录时，只显示一张强化卡：

> 你正在重听 N 天前记录过的这首歌。

主按钮直接进入盲听重评。

## 8. 盲听重评

### 8.1 页面

盲听页面显示歌曲身份和封面，但提交前不加载到可见界面的内容包括：

- 首次评分和评分修饰符。
- 首次情绪。
- 首次正文。
- 以前的 ListeningMoment。
- 评分变化图。

页面字段：

- 当前综合评分，可为空。
- 当前评分修饰符，仅在评分存在时有效。
- 当前情绪，可为空。
- 一句话感受，必填。
- 收听日期，默认当前本地日期。

### 8.2 保存

提交创建 ListeningMoment，并保持 ReviewEntry 不变。

保存成功后进入揭晓状态。保存失败时保留输入并允许重试，不提前展示旧评价。

第一版不为盲听表单增加草稿。页面退出时如果有未保存输入，使用离开确认；该决定限制了 v2.1.7 的范围，也避免给 ListeningMoment 建立第二套草稿协议。

## 9. 变化揭晓

揭晓计算为纯函数，不写回额外分析结果。

### 9.1 时间

使用首次 ReviewEntry 的 listenedAt 与本次 ListeningMoment 的 listenedAt 计算本地自然日差。

### 9.2 评分

- 两次都有数值评分时显示起点、终点和数值差。
- 任一次缺少评分时只展示已有值，不制造差值。
- + 和 - 作为展示修饰符保留，不参与数值差换算。
- 文案只使用“上升、下降、相同、未评分”。

### 9.3 情绪

对规范化后的情绪集合计算：

- 保留：两次都有。
- 新增：本次有、首次没有。
- 淡出：首次有、本次没有。

“淡出”只描述本次选择差异，不解释为永久消失。

### 9.4 原文

并列展示首次 ReviewEntry.content 与本次 ListeningMoment.content。应用不自动概括、改写或解释。

## 10. 本地记忆卡

### 10.1 卡片种类

v2.1.7 固定提供两类、同一视觉系统的竖版 PNG：

1. 快速记录卡：封面、歌曲、歌手、评分、情绪、正文摘录、日期。
2. 重听对比卡：两次日期、两次评分、两组情绪、两段正文摘录、相隔天数。

第一版不提供主题选择器。

### 10.2 隐私开关

导出预览页提供四个独立开关：

- 隐藏正文。
- 隐藏评分。
- 隐藏日期。
- 隐藏“小懂哥”名称。

开关只影响生成图片，不修改原始记录。

### 10.3 渲染与保存

- 使用浏览器原生 Canvas 生成 PNG，不新增图片渲染依赖。
- 使用固定逻辑像素尺寸和设备无关缩放。
- 封面绘制失败时使用内置占位构图，文字仍可导出。
- 正文按字符和实际测量宽度截断，不能缩小到不可读。
- Web 使用现有下载方式。
- Android 使用现有 Filesystem 能力写入 Documents，PNG 数据使用 base64，不指定 UTF-8 文本编码。
- 保存失败时保留预览和重试按钮，不影响记录或 ListeningMoment。

## 11. 数据与备份

### 11.1 数据使用

| 数据 | 用途 |
| --- | --- |
| ReviewEntry | 快速记录、完整乐评、今日重逢来源 |
| ListeningMoment | 盲听重评与重听历史 |
| EntryDraft | 快速和完整记录草稿 |
| AppData | 当日重逢引用与隐藏状态 |
| CoverImage | 页面和卡片封面 |

### 11.2 SQLite

核心功能不新增表和列：

- 快速记录写入现有 ReviewEntry。
- 重听写入现有 ListeningMoment。
- 今日重逢状态写入现有 AppData。

因此不新增原生 SQLite schema 迁移。

### 11.3 备份

当前 v5 备份已经包含 entries、listeningMoments、covers 和 appData。新增 AppData 键能够随现有 v5 备份传输，因此不提升备份版本。

旧 v5 备份没有今日重逢状态时按“当天尚未计算”处理。

草稿当前不属于正式备份数据，本版本保持该边界；快速草稿不会被 JSON 备份导出。

## 12. 代码边界

新增或定向拆分为：

- quickCapture.ts：快速记录输入、最近情绪和 EntryInput 转换。
- QuickCapturePage.tsx：快速记录界面、当前播放复查和草稿衔接。
- musicIdentity.ts：严格音乐身份匹配，与日期重复检测分离。
- resurfacing.ts：今日重逢合格条件、排序和当日状态。
- RelistenPage.tsx：盲听输入、保存和揭晓页面。
- relistenComparison.ts：日期、评分、情绪和原文比较。
- shareCard.ts：卡片布局、Canvas 渲染和 PNG 输出。

App.tsx 只保留路由接入、首页入口和共享壳层；本次触及的快速记录、重听和卡片页面不再继续内嵌到 App.tsx。

store.ts 只增加本版本需要的窄接口：

- 读取和写入今日重逢 AppData。
- 查询某记录最近一次 ListeningMoment。
- 读取卡片和重逢所需数据。

不得借本版本重写全部存储层。

## 13. 路由与导航

新增路由：

- /capture：快速记录。
- /relisten/:entryId：盲听重评。

没有 moment 查询参数时，/relisten/:entryId 显示盲听输入。保存成功后使用 replace 导航到 /relisten/:entryId?moment=:momentId，并从存储读取该 ListeningMoment 后显示揭晓，因此刷新后能够恢复。moment 不存在或不属于当前 entryId 时显示错误和“重新开始”按钮；按钮清除查询参数后返回新的盲听输入，不静默展示错误记录。

现有 /new 继续表示完整乐评，不改变旧链接。

首页、记录详情页和歌曲聚合页都可以进入 /relisten/:entryId，但只有首页提供“今日重逢”自动选择。

## 14. 错误与降级

- 当前播放权限关闭：展示开启系统权限入口，同时允许手动快速记录。
- 当前播放为空：显示手动填写音乐信息，不报错阻断。
- Apple 目录请求失败：保留原生读取字段，继续记录。
- 严格身份匹配出现多个结果：要求用户选择，不自动合并。
- 快速草稿写入失败：显示错误并阻止离开当前内容。
- 今日重逢状态损坏：丢弃该 AppData 值并重新计算，不影响记录。
- ListeningMoment 保存失败：保留盲听输入，不展示旧评价。
- 封面加载失败：使用占位图。
- Canvas 生成失败：记录保持已保存，卡片可重试。
- Android 文件写入失败：显示具体保存失败信息，不报告记录失败。
- 任意分析或卡片错误不得修改 ReviewEntry 或 ListeningMoment。

## 15. 可访问性与交互

- 每页只有一个主操作。
- 触控目标至少 44×44 CSS 像素。
- 快速记录的情绪按钮支持键盘焦点和明确选中状态。
- 评分不只用颜色表达。
- 揭晓中的上升和下降同时显示文字与数值。
- 卡片隐私开关具有可读标签。
- 支持系统大字体；长文本改为增高或截断，不允许横向溢出。
- 遵循系统减少动态效果设置；揭晓动画不是读取内容的前提。
- 离开未保存的盲听表单需要确认。

## 16. 验证

### 16.1 纯逻辑检查

- 当前播放字段完整、部分缺失和权限关闭。
- catalogTrackId 严格匹配。
- 歌曲与歌手规范化匹配。
- 只有歌曲名时不自动匹配。
- 多条匹配时不自动选择。
- 最近使用情绪最多 6 个、去重且不自动选中。
- 快速输入转换为合法 EntryInput。
- 本地日期跨月和跨年转换。
- 今日重逢 30 天、90 天和周年 7 天边界。
- 最近 30 天已有 ListeningMoment 时排除。
- 同一天选择稳定。
- 当日记录删除后重新计算。
- 评分上升、下降、相同和缺失。
- 情绪保留、新增、淡出和空集合。
- 长正文截断及隐私开关。

### 16.2 草稿与存储

- 快速草稿自动保存和恢复。
- 快速草稿展开为完整模式不丢字段。
- 旧草稿按完整模式恢复。
- ReviewEntry 创建后快速草稿清理。
- 原生 SQLite 和 Web 存储结果一致。
- ListeningMoment 创建、查询和删除级联不回归。
- 今日重逢 AppData 损坏后安全恢复。
- v5 备份导出和恢复包含新增 AppData 状态及 ListeningMoment。
- 旧 v5 备份继续可导入。

### 16.3 页面与产物

- 快速记录、完整乐评和再次听见入口均可到达。
- 写作中重新读取不同歌曲不会覆盖输入。
- 盲听提交前旧评价不可见。
- 保存成功后揭晓可刷新恢复。
- 中文、英文、Emoji 和长文本卡片不溢出。
- 无封面时卡片正常生成。
- Web PNG 下载。
- Android Documents PNG 写入。

## 18. 成功标准

- 用户能够从首页在 60 秒内保存一条真实、有效且可继续编辑的快速记录。
- 当前播放已有严格匹配档案时，应用不会静默创建重复记录。
- 快速草稿与完整草稿共享现有草稿箱并保持向后兼容。
- 首页在有合格数据时稳定展示一条今日重逢，无数据时不出现空入口。
- 盲听提交前不泄露旧评分、情绪和正文。
- 重听保存为 ListeningMoment，不修改首次记录。
- 揭晓只描述评分、情绪、原文和时间的事实差异。
- 两类卡片在 Web 和 Android 均可生成，隐私开关有效。
- 不新增 SQLite 表，不提升 v5 备份版本。
- 旧记录、旧草稿和旧 v5 备份保持可用。
